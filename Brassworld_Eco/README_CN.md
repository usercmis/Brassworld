# Brassworld 环保模式：前端与后端代码

## 先读这个

这是两个可以分别交给前端、后端成员的程序目录，以及一个可本地运行的联调演示。

**环保规则已实现；演示的基础经济玩法经过简化，不是完整 Brassworld 的替代品。**
原来的本地项目 `serve.py` 将行动转发给原游戏服务器，我们没有那个服务器的完整规则源代码。
因此不能用这个包直接覆盖现有 Render 项目，也不能承诺它能直接修改原服务器的规则。
完整接入方式见 `INTEGRATION_CN.md`，需要连接到你们自己控制的基础规则引擎。
现有游戏、背景音乐、地图文件均没有被改动。演示不依赖原服务器，无需下载额外 Python 包。

## 1. 前端程序在哪里

| 文件 | 内容 |
|---|---|
| `frontend/index.html` | 英文页面结构、模式选择、行动确认弹窗 |
| `frontend/style.css` | 纸张、墨色、绿色环保提示的响应式样式 |
| `frontend/app.js` | 从后端读取局面，显示污染、费用、绿色分和合法行动；发送选择结果 |
| `frontend/eco-panel.js` | 可复用的环保面板模块，供朋友接入原游戏前端 |

前端不决定费用、污染、归属、胜利分和行动合法性。它只提交后端生成的行动 id 和版本号。
演示中的基础厂牌、城市等均为文字卡片，不是原地图的替换文件。

## 2. 后端程序在哪里

| 文件 | 内容 |
|---|---|
| `backend/eco_rules.py` | 独立环保规则：污染、建造附加费、治理、改造、出售排放、最终奖励 |
| `backend/integration.py` | 连接自有完整规则引擎的事务适配器，明确每个原规则接口的职责 |
| `backend/demo_game.py` | 独立演示的简化基础引擎，用来实际验证环保模块 |
| `server.py` | 本地 HTTP API、SQLite 存档、浏览器会话隔离、版本检查 |
| `tests/test_eco.py` | 规则测试、事务回滚测试和 HTTP 联调测试 |

规则模块与 Python 标准库服务器均无需 pip install。Python 要求 3.10 或以上。

## 3. 已实现的环保规则

| 规则 | 数值与时机 |
|---|---|
| 开关 | 新局选择 Standard / Eco Mode，局中不切换 |
| 污染 | 每个城市 0–10，共享；正常新局从 0 开始 |
| 出售排放 | 棉纺厂 COTTON +1，制造厂 MFG +2，陶器厂 LUX +3 |
| 其他厂 | 煤、铁、啤酒本身不触发环保排放 |
| 污染费用 | Build 执行前城市污染 ≥6，额外支付 £5；所有玩家一样 |
| 治理 Clean Up | £5、1 行动、1 弃牌；自己有厂的城市污染 −3，最低 0 |
| 环保改造 Eco Upgrade | £8、1 行动、1 弃牌；仅自己的、未出售销售类工厂，每厂一次 |
| 改造效果 | 该厂 Sell 的污染 −2，最低 0；没有即时绿色奖励 |
| 绿色奖励 | 改造厂成功 Sell 时 +2 绿色分，每厂一次 |
| 最终结算 | 每绿色分换 1 VP，只在整局结束加入一次；不是每个时代都加 |
| 跨时代 | 污染、绿色分保留；仍在场的工厂保留改造状态 |
| 普通模式 | 无污染排放、附加费、治理和改造，基础玩法由原引擎决定 |

新增行动遵循“一次行动弃一张牌”；完整接入时玩家可以选弃牌，原引擎验证并移除。
改造后的棉纺厂排放 0，制造厂排放 0，陶器厂仍排放 1。
治理要求城市中存在自己的工厂，可以是已翻面的厂；不允许对污染已经为 0 的城市浪费治理。
清理只改变污染，不退还之前支付的附加费。附加费计入本轮花费，影响原版行动顺序。
多厂一次 Sell 必须逐厂计算污染，但整个 Sell 仍由基础规则决定行动数和弃牌数。

## 4. 本地打开演示

1. 解压整个 ZIP，不要只拖出 HTML。
2. Windows：双击 `start_windows.bat`；或终端进入这个目录运行 `py -3 server.py`。
3. Mac：终端进入目录，运行 `python3 server.py`。
4. 浏览器打开 **http://127.0.0.1:3001**。
5. 选择 Eco Mode，点击 Start scenario。
6. 两个人在同一个设备轮流操作；它不是网络多人房间。

服务器要一直保持运行。停止时在终端按 Ctrl+C。端口占用时可用 `python3 server.py --port 3002`。
这是本地程序，不能直接双击 `index.html` 使用后端。

## 5. 建议的验证流程

开局 Anni 有 £45，Riga 啤酒厂、Rotterdam 制造厂、New York 陶器厂。
为了立刻测试污染阈值，**演示特意把 New York 污染设为 5、Marseille 设为 6**。
正式新局应调用 `EcoRules.initialize`，所有城市初始污染是 0。

1. 在行动类型选择 Eco Upgrade，改造 Rotterdam 制造厂，确认现金 −£8。
2. 再选择 Sell，出售该厂，使用 Riga 啤酒。
3. 检查 Rotterdam 排放为 0，绿色分变为 2，Riga 啤酒耗尽并翻面。
4. 换对手操作，观察城市污染对两位玩家共享。
5. 查看 Marseille 建厂费用，包含 £5 附加费。
6. 在拥有自己工厂的污染城市进行 Clean Up，观察减 3、扣 £5、用一次行动。
7. 用 Pass 快进到第 8 轮结束，检查绿色分只加一次 VP。
8. 刷新网页：同一浏览器会从 SQLite 恢复局面。
9. 新开无痕窗口：它是另一个会话，不会读到原会话的局面。

## 6. 演示与完整游戏的区别

为保证不把不存在的原版后端能力伪装出来，演示清楚限制为环保测试场：

- 6 座城市、2 位真人同屏轮流操作、8 轮、每时代 4 轮。
- 只演示棉纺、制造、陶器、啤酒四类厂，以及 Sell、Loan、Pass 和两个环保行动。
- 没有原版地区牌匹配、运输网络、港口商品限制、煤铁供给、科技供应和覆盖规则。
- 不提供原版 AI；不把旧 AI 当成理解环保规则的新 AI。
- 基础收入使用直接增量，不模拟原版非线性收入轨。
- 演示每行动自动弃 1 张抽象牌，轮末补回 8 张；不是真正牌堆。
- 演示旧工厂跨时代保留，用于测试环保状态；不模拟原版一级厂移除。
- 啤酒选择只演示自己的啤酒，不模拟商人和对手啤酒。

这些简化均限于 `demo_game.py`。`eco_rules.py` 可以接到真实完整规则引擎上，不应拿演示替换原版规则。

## 7. 原代码需要删除什么

**不需要删除原文件。** 先在一个新目录运行这个包，与原版并存。

如果朋友有完整后端，按 `INTEGRATION_CN.md` 接入，保留原地图、资源、卡牌和计分逻辑。
如果朋友只有代理服务器，就不能仅替换前端或复制 `eco_rules.py` 完成完整接入。
需要先把基础规则引擎放到自己的服务器；不要通过反复修改远端 save 来假装支持事务。

## 8. 测试

在项目根目录运行：

```sh
python3 -m unittest discover -s tests -v
```

测试涉及费用阈值、污染封顶、改造/治理权限、资源耗尽、重复奖励、最终计分、版本冲突、事务回滚和会话隔离。
SQLite 文件默认在项目根目录 `eco.sqlite3`；该文件是运行数据，不包含在代码包中。
可用环境变量 `ECO_DB_PATH` 指向持久磁盘路径。当前服务是本地测试服务，尚非面向公开玩家的生产房间系统。

## 9. 分工

- 前端成员：`frontend/`，把污染数字、附加费与绿色分接到原地图和行动预览。
- 后端成员：`backend/eco_rules.py`、`backend/integration.py`，实现原引擎适配、原子存档和合法行动生成。
- 你：确认规则数值，比较“直接出售”和“先改造再出售”两种策略，记录试玩反馈。
- 测试成员：验证普通模式不变、新规则对所有玩家一致，特别检查 AI、时代结束、多厂出售和重复点击。
